# Git 与版本保存

## 初始化前判定

检查 Git 根目录、当前分支、改动、origin 和提交身份；沿用本项目身份/认证，不改全局身份。身份缺失时询问。线上地址使用不带密码/token 的 HTTPS 或 SSH URL，认证走凭据管理器/SSH。

用 `git ls-remote "<remote>"` 区分**可访问的空仓库、已有历史、访问失败**：

| 情况 | 操作 |
|---|---|
| 本地为空、远端为空 | 运行初始化脚本。 |
| 本地为空、远端有历史 | clone 到目标位置，再补齐规范；不运行空目录脚本覆盖。 |
| 本地已有内容 | 保留文件、改动与历史，先确认远端对应关系再增量整合；不同 origin 或实质冲突需澄清。 |
| 远端访问失败 | 解决具体连接/认证问题；不能当成空仓库，不宣称线上初始化成功。 |

新仓库默认 main，已有仓库保留有效分支。不擅自新建线上仓库、改变可见性、强推、硬重置或改绑 origin。

## 每轮提交与推送

已确定 origin 并采用每轮推送约定后直接执行；用户后来要求只保留本地时以新要求为准。

1. 写好讨论、当前状态和 HTML，以讨论编号关联，例如 `iteration(20261029-1530-layout): organize project`。
2. 查看精确暂存文件及差异，只提交本轮相关路径。有无关已暂存改动时按路径提交，保留它们原有状态；不用未检查的 `git add .`，不清空用户暂存区。
3. 提交后推送当前分支，首次设置 upstream。只推相关分支/指定标签，以成功回执确认远端接收。失败保留本地提交并说明原因；远端领先先获取差异再整合，不用强推解决。

代码、依赖/非秘密配置、项目 Skill、讨论、HTML、紧凑结果和允许分享的参考笔记进入 Git；**不能整体忽略 outputs**。凭据、环境/索引/临时文件不上传。data/state/logs 默认留本地，小型合成测试样本可放项目约定的测试目录跟踪。

受限原件或大型产物按许可、体积及用户认可的存储方式安排；需要时才引入 LFS/外部存储。未进 Git 的必要材料记录来源版本、位置和获取/重建方法；只有本地副本就写“未线上备份”。忽略规则不会清除已跟踪文件或历史中的秘密。

文档用讨论编号定位，最终回复给真实提交号和 push 结果；不要为回填文档自身 hash 反复提交。推送状态按实际执行报告，写入文档的既往同步状态注明对应版本，避免误指当前未推送修改。

## 冻结、对比与导出

普通提交保存讨论版本。明确冻结或正式里程碑时，在包含代码、必要配置、结论和报告的提交上建立 annotated tag，例如 `freeze/v1.0-20261029`。注释列讨论编号、范围、结果/输入位置及未验证事项，再推送这个标签。旧标签不重指，修正用新版本。

```text
git show <tag>:docs/project-status.md
git diff <old-tag>..<new-tag> -- <需比较的实际路径...>
```

数字结果比较还需核对输入和参数口径。Git 树已保存当时的代码和结论，不常态复制整项目到 version。

需要独立交付包时，才从**指定冻结提交**用 git archive 导出到 outputs/releases/<version>；仅选择必要路径，排除既往 releases，避免递归打包。附标签/commit、运行条件及输入依赖说明；数据快照另按实际存储安排，源码冻结不代表数据已备份。
